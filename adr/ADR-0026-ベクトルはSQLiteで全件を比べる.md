# ADR-0026: ベクトルはSQLiteに置き、検索のたびに空間の全件を比べる

- 日付: 2026-10-22
- 状態: Accepted
- 関連: ADR-0003（Embedding空間の分離）、PRD §14（ベクトル検索の実装）、#35

## Context
PRD §14では、ベクトル検索はSQLiteとバッチでの類似度の走査から始め、必要なら近似最近傍（ANN）かRustにするとしている。ベクトルは空間ごとに分けて持つ（ADR-0003）。

## Decision
- ベクトルはSQLiteのDBに、空間、対象、revisionごとに保存する。
- 検索では空間のベクトルをSQLiteから順に読み、内積で上位を残す。ベクトルはL2で正規化しているので、内積がコサイン類似度になる。利用できるファイルの、今のrevisionのベクトルだけを比べる。
- ANNの索引は作らない。

## Consequences
索引の構築や更新の手間がなく、ベクトルの追加と削除がDBのトランザクションに収まる。検索の時間はベクトルの数に比例する。3万件の768次元では1回の検索で約90 MBを読む。実機で時間を測り、遅ければANNを検討する。
