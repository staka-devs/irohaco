# ADR-0028: GPUとCPUは利用者が選び、GPUで動くかは別のプロセスで確かめる

- 日付: 2026-10-28
- 状態: Accepted
- 関連: ADR-0002（リモートへ切り替えない）、ADR-0021、ARCHITECTURE §10.1、#165、#169

## Context
LiteRT-LMのGPUバックエンドは、端末のOpenCLで動く。GPUのドライバはネイティブの層で異常終了することがあり、アプリの中ではcatchできない。#165ではGPUで落ちたら次からCPUで動かすようにしたが、この切り替えは利用者に見えず、1回は落ちる。

## Decision
- manifestで`libOpenCL.so`と`libvndksupport.so`を`required="false"`で宣言する。宣言がないと、アプリは端末のOpenCLを読み込めない。
- GPUで動くかはモデルのファイルを初めて読み込む前に、別のプロセス（`:gpu_probe`の`GpuProbeService`）で確かめる。そのプロセスでモデルをGPUに読み込み、文字と画像を1つずつベクトルにする。プロセスが落ちるか失敗したら、GPUは使えないとみなす。終わるとプロセスを終了し、メモリを返す。
- 確かめた結果はモデルのファイルごとに保存し、同じファイルでは確かめ直さない。
- 設定のAIで、GPUとCPUを選べる。選ばれていないうちは、GPUが使えればGPU、使えなければCPUで動かす。GPUが使えない端末では、GPUを選べなくして理由を出す。
- 選んだほうで読み込めなければ、もう一方に切り替えずに失敗とする。選び直したら、読み込んだモデルを解放する。

## Consequences
GPUのドライバが落ちても、アプリは落ちない。どちらで動いているかを利用者が知り、選べる。確かめる間は、別のプロセスがモデル1つ分のメモリを使う。別のプロセスが落ちたときにシステムがエラーの画面を出すかは、実機で確かめる。

## Rejected alternatives
- GPUで失敗したら黙ってCPUに切り替える（#165）: 利用者に見えず、ドライバが落ちる端末では1回はアプリが落ちる。
- OpenCLのライブラリがあるかだけを確かめる: ライブラリはあってもドライバで落ちる端末を見分けられない。
