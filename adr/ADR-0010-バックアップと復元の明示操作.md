# ADR-0010: バックアップと復元は明示的な操作で行う

- 日付: 2026-10-18
- 状態: Accepted（SQLiteの参照設計は検証済み。エクスポートはRoomで実装済み。復元とAndroid実機での検証は未実施）
- 関連: `../database/DATABASE_DESIGN.md`、`../docs/implementation/USE_CASES.md`、ADR-0005（3NF必須）

## Context
既定では完全にローカルで動かすことと、安全に機種を変更できることを両立する必要がある。

## Decision
OSの自動クラウドバックアップは既定で無効にする。暗号化した手動のエクスポートを使い、復元は、検証、候補の照合、プレビュー、確認、適用、検査の段階を踏んで行う。原本、APIキー、外部送信の許可、OSの権限は、既定では持ち運ばない。

ファイルの形式と暗号化は次のとおりとする。
- 鍵はパスフレーズからArgon2idで作る。設定はRFC 9106の2番目の推奨値（メモリ64 MiB、3回、4レーン）とし、ソルトは16バイトとする。Argon2idはBouncy Castle（`bcprov-jdk18on`）を使う。
- 本文はAES-256-GCMで暗号化する。AES-GCMはAndroid標準の`javax.crypto`を使い、ノンスは12バイトとする。
- ファイルの先頭には、形式の名前、コンテナの版、Argon2idの設定、ソルト、ノンスを平文で置く。この先頭部分も、GCMの追加認証データとして改ざんを検出する。
- 読むときは、Argon2idの設定とファイルの大きさに上限を設ける。上限を超えるファイルは、鍵を作る前に拒否する。
- 本文はJSON（`format_version=1`）とする。manifestに各記録のSHA-256を持ち、読むときにすべての記録をmanifestと照らし合わせる。
- パスフレーズは8文字以上とし、アプリには保存しない。
- 書き出したファイルは読み直して検証し、通ったときだけ`backup_archives`をVERIFIEDにする。失敗したときはFAILEDにして、ファイルを消す。

## Consequences
機種を変えるときにユーザーがパスフレーズを管理し、復元のときにプレビューを確かめる手間が増える。その代わり、秘密情報や許可が意図せず持ち出されることを防げる。

## Rejected alternatives
暗号化していないJSONを通常のDownloadsへ定期的に書き出す方式、データベースのファイルを検証せずに置き換える方式。
