# ADR-0005: 正本データベースは最低でも第三正規形を必須とする
- 状態: Accepted
- 日付: 2026-10-18
- 設計資料: [`../database/DATABASE_DESIGN.md`](../database/DATABASE_DESIGN.md)

## Context
複数モデル索引、動画セグメント、メタデータ、タグ、アルバム、EXIF推定根拠を単一のJSONやワイドテーブルへ押し込めると、更新異常・削除異常・不整合が生じる。アプリは外部ファイルの変更や端末移行にも耐える必要がある。

## Decision
- **すべての正本関係に最低3NFを義務付ける。** ER図、候補キー、関数従属性のレビューをPRの必須項目とする。
- 繰り返し要素（タグ、能力、場所推定根拠、検索条件の値、Embedding空間とのM:N）は関連テーブルに分ける。
- メディアIDとMediaStore ID、動画とフレーム、モデル接続先とモデル、モデルとEmbedding空間、元EXIF値とユーザーのオーバーライドを分離する。
- 物理化された検索インデックス、FTS/ANN、キャッシュ、画面向けDTOは派生Read Modelであり再構築可能にする。**派生モデルでの非正規化を理由に正本を非3NF化しない。**
- SQLiteのCHECK/FK/UNIQUE/Triggerをできるだけ併用し、RoomのMigrationTestとビジネス関数従属性の手動レビューを両方実施する。
- 3NF違反が不可避と判断される変更は暗黙に実装せず、モデルの再設計または明示ADRの議論と合意を必要とする。本決定を既定のまま緩和しない。

## Rejected alternatives
- メディア行へtags・OCR・推定位置・EmbeddingをJSON配列で詰め込む方式。
- 検索性能を理由に正本カラムへモデルURL・タグ名・album名を複製する方式。
- モデルごとに独立DBを用意しユーザーデータまで複製する方式。

## Consequences
JOINが増える一方で、変更の局所性・参照整合性・モデル差し替え耐性が高まる。必要な性能改善は`FTS/ANN`やRead Modelで行う。**3NFを満たすことは仕様レビューで保証対象とし、自動テストだけで形式的に証明したとは扱わない。**
